# التكليف التنفيذي الشامل إلى Qiyas / Claude — النسخة 1.1

أنت Qiyas، والمطلوب منك تنفيذ ملكية دستورية وتنفيذية كاملة في مشروع Hokom–Taaqol، لا إجراء تعديل موضعي. نفّذ المهمة من البداية إلى النهاية: **معالجة الحادثة السابقة والتحقق من نظافة البيئة أولًا، ثم التدقيق القرائي، ثم مطابقة الواقع البرمجي، ثم تنفيذ الفجوات فقط، ثم الاختبارات، ثم التقرير النهائي**. لا تسأل عن تفاصيل يمكن حسمها من المستودع والدستور، ولا تتوقف عند الخطة إذا كان التنفيذ ممكنًا.

## الهدف
إدماج «التعديل الدستوري الأول: منشأ الادعاء، بناء المفهوم، ترخيص الحكم، الأثر، المطابقة، والمراجعة» في المعمار الحالي دون إنشاء سجل طبقات موازٍ، ودون كسر SCG أو P0–P12 أو مخرجات Verifier أو سلم الأدلة أو ملكية Hokom الصرفية.

## الحالة السابقة الملزمة للتحقق — حادثة سلامة تنفيذ
ورد تقرير سابق يفيد بأن وكيلًا سابقًا أدخل أو عدّل عناصر محظورة، ثم ادعى إصلاحها. لا تعامل ذلك التقرير على أنه برهان نظافة، بل على أنه **إشعار حادثة** يجب التحقق منه مباشرة من الشجرة وHEAD. العناصر المبلغ عنها هي:

1. `strenum_compat.py`: شيم أو backport لـ`StrEnum`، ثم استبداله بملف يرفع `ImportError` بدل حذفه.
2. `conftest.py`: تعديل أو حقن يؤثر في مجرى pytest.
3. `vendor/Taaqol-GPT/tests/conftest.py`: ملف منشأ داخل شجرة vendor لحقن التوافق.
4. `admission_gate.py`: حقن `StrEnum` في الوحدة القياسية `enum` قبل الاستيراد.
5. بيئات افتراضية مضللة أو مؤقتة، منها اسم `.venv-py311` مع تقرير أنه يشغل Python 3.10.12، وذكر `.venv-py310-tmp` في موضع آخر.
6. ادعاء أن Step 6 مغلق مع عدم إثبات تشغيله واختباره على Python 3.11 الأصلي.

**الاستنتاج الملزم:** الحالة السابقة `CONTAMINATED_OR_UNVERIFIED`. واستبدال ملف محظور بملف يرفع خطأ ليس حذفًا، وقراءة الكود لا تكفي لإعلان `CLOSED`.

## المرحلة 0 — بوابة المعالجة والنظافة قبل أي تنفيذ جديد
لا تكتب ميزة جديدة، ولا تعدل الدستور، ولا تبدأ دمج العقود قبل اجتياز هذه البوابة. المسموح قبلها هو التحقق والمعالجة المباشرة للحادثة فقط.

### 0.1 تثبيت حالة المستودع
سجل دون تغيير:
- مسار المستودع والفرع و`HEAD`.
- `git status --short --untracked-files=all`.
- `git diff --stat` و`git diff` للملفات المبلغ عنها.
- الملفات المتتبعة وغير المتتبعة، مع استخدام `git ls-files` لإثبات أصل كل ملف.
- أي تغييرات سابقة لا تخص هذه المهمة؛ لا تمحها ولا تخفها.

### 0.2 إزالة الآثار المحظورة إزالة حقيقية
- إذا كان `strenum_compat.py` غير متتبع ومنشأ للحادثة: احذفه فعليًا. لا تستبدله بملف يرمي استثناءً.
- إذا كان `vendor/Taaqol-GPT/tests/conftest.py` غير موجود في `HEAD` ومنشأ للحادثة: احذفه فعليًا. لا تترك stub أو sentinel.
- إذا كان `conftest.py` متتبعًا: استعد النسخة المطابقة لـ`HEAD` أو للbaseline المعتمد، ولا تحتفظ بأي حقن أو تغيير collection أو import hook غير مأذون.
- افحص `admission_gate.py` وأزل أي monkey patch أو `setattr` أو حقن في `enum` أو `sys.modules` أو استيراد لـ`strenum_compat`. لا تحذف منطق Step 6 المشروع إلا بقدر ما يثبت أنه جزء من الحقن المحظور.
- افحص كامل المستودع بحثًا عن: `StrEnum`, `strenum_compat`, `setattr(enum`, `enum.StrEnum`, `sys.modules`, `monkeypatch`, وحقنات pytest المشابهة.
- أثبت أن `git diff -- vendor/Taaqol-GPT` خالٍ من تغييرات هذه الحادثة. لا تعدل vendor لحل مشكلة runtime.

### 0.3 سلامة بيئة Python
لا تثق باسم البيئة الافتراضية. أثبت البيئة الفعلية بتسجيل:
- `command -v python` و`command -v python3.11` إن وجد.
- `python -c "import sys; print(sys.executable); print(sys.version)"`.
- `python -c "from enum import StrEnum; print(StrEnum)"` داخل البيئة المرشحة.
- إصدار pip ومسار تثبيت Taaqol.

القواعد:
- لا شيم، لا backport، لا monkey patch للوحدة القياسية، ولا حقن عبر `conftest.py`.
- إذا كانت البيئة المسماة `.venv-py311` لا تعمل فعلًا على Python 3.11، فلا تستخدمها ولا تصفها بأنها 3.11. أزلها أو أعد إنشاءها فقط بعد إثبات أنها بيئة مؤقتة غير متتبعة ولا تحتوي عملًا يدويًا.
- افحص كلًا من `.venv-py311` و`.venv-py310-tmp`؛ اختلاف الاسم في التقرير السابق تناقض يجب حسمه من filesystem، لا بالتخمين.
- إذا لم يتوفر Python 3.11 الأصلي، لا تحاول محاكاته. صنف التفعيل `DEFERRED_RUNTIME_PY311` وواصل فقط ما يمكن إثباته دون ادعاء الإغلاق.

### 0.4 إعادة خط الأساس والتحقق من Step 6
بعد النظافة فقط:
- شغّل baseline دون تعديل test harness.
- شغّل اختبارات Step 6 والتكامل على Python 3.11 الأصلي إن توفر.
- تحقق أن الاستيرادات تأتي من Taaqol الفعلي، لا من shim أو مسار محلي بديل.
- لا تصنف Step 6 `CLOSED` إلا إذا اجتمعت: نظافة الشجرة، runtime أصلي 3.11، نجاح الاستيراد، نجاح الاختبارات المستهدفة، وعدم تعديل vendor أو test harness.
- إذا كان الكود مكتوبًا ولم يمكن تفعيله واختباره، فالحالة الصحيحة: `IMPLEMENTED_DEFERRED_ACTIVATION` أو `PARTIAL`، لا `CLOSED`.

### 0.5 مخرج بوابة الصفر
قدم قبل التنفيذ تقريرًا موجزًا بهذه الحقول:
- `INCIDENT_VERDICT`
- `PROHIBITED_FILES_STATUS`
- `VENDOR_INTEGRITY`
- `TEST_HARNESS_INTEGRITY`
- `RUNTIME_PROOF`
- `STEP6_STATUS`
- `CLEANUP_DIFF`

لا تنتقل إلى المرحلة A إلا إذا كانت آثار الحادثة مزالة أو معزولة بوضوح، ولم يعد هناك مسار حقن نشط. إذا منعك filesystem أو الصلاحيات من الحذف الحقيقي، لا تدّع الإصلاح؛ اذكر `BLOCKED_CLEANUP` والمسار والأمر اللازم حرفيًا.

## حقائق محصنة
1. السجل الكنسي الحالي 19 طبقة موزعة على P0–P12؛ لا تعيد ترقيمه ولا تنشئ سجلًا موازيًا.
2. P12 نهائي من نوع `IfadahCandidate` ولا يفتح P13 ولا ينتج معنى أو حكمًا نهائيًا.
3. نطاق Hokom الحالي متوقف عند P5 ما لم يثبت المستودع أو تعليمات لاحقة خلاف ذلك؛ لا تفتح P6–P12 بحجة هذا التعديل.
4. سلسلة الحكم: الوضع → السبب → الشرط → المانع → العلة → القادح → الصحة → الفساد → البطلان → الأثر → البقايا.
5. Verifier يخرج `Licensed / Blocked / Deferred / Residual`.
6. افصل `intrinsic_verdict` عن `operational_status` وعن `evidence_rank`.
7. `Rank(conclusion) ≤ min Rank(required premises)`.
8. المانع النشط يمنع `Licensed`، والدليل اللازم المفقود ينتج `Deferred` لا `Batil`.
9. الجذر والوزن والمصدر والمشتقات ملك Hokom؛ HR2S مصدر مرشح أو دليل فقط.
10. لا فعل أو معنى نهائي من `Concept` أو `IfadahCandidate` أو `CandidateRule` مباشرة.
11. لا زرع لأمثلة مخصوصة، ولا تعديل صامت، ولا ادعاء تنفيذ بمجرد وجود اسم أو وثيقة.
12. test harness وvendor وruntime جزء من دليل التنفيذ، ولا يجوز تعديلها لتصنيع نجاح الاختبارات.
13. لا إعلان `CLOSED` دون تشغيل مثبت على البيئة الكنسية المطلوبة.

## ترتيب مصادر الحقيقة عند التعارض
الدستور والمواد المحصنة → سجل SCG → العقود والمخططات الكنسية → الاختبارات المعتمدة غير الملوثة → التنفيذ الجاري → الوثائق التفسيرية.

## المرحلة A — تدقيق قرائي إلزامي قبل أي كتابة وظيفية
- ثبت حالة المستودع والفرع وHEAD والملفات المعدلة بعد اجتياز بوابة الصفر.
- اكتشف المسارات الفعلية ولا تفترضها.
- اقرأ الدستور وسجل SCG والعقود والschemas والenums ومسارات Verifier وP12 والtrace/residuals.
- ابحث عن العقود أو المعاني القائمة: `ClaimProvenance`, `ConceptContract`, `IfadahCandidate`, `RealityDomain`, `DomainBridge`, `Assessment`, `TransitionTrace`, `RepairDirective`, `CorrespondenceAssessment`, `AuthorityCheck`، وسلسلة الوضع/السبب/الشرط/المانع/العلة/القادح/الصحة/الفساد/البطلان.
- ارسم تدفق البيانات الفعلي وحدد المالك لكل وظيفة.
- تحقق من ملكية الجذر والوزن والمصدر والمشتقات ومن حدود HR2S.
- شغّل الاختبارات قبل التعديل وسجل baseline وNode IDs إن أمكن.
- صنف كل مطلب: `IMPLEMENTED / PARTIAL / MISSING / CONFLICT / DOCUMENTED_ONLY / OUT_OF_CURRENT_SCOPE`.

## المرحلة B — نفذ الفجوات دون ازدواج
1. أضف التعديل الدستوري الأول واربطه بالدستور وفهرس الوثائق الحاكمة.
2. أعد استعمال الموجود الصحيح، ووسع الأنواع بدل إنشاء نسخ مكررة.
3. نفذ أو وحّد الحد الأدنى الدلالي للعقود التالية:
   - `ClaimProvenance`
   - `ConceptContract`
   - `IfadahCandidate`
   - `RealityDomain`
   - `DomainBridge`
   - `Assessment` بفصل `intrinsic_verdict / operational_status / evidence_rank`
   - `TransitionTrace`
   - `RepairDirective`
   - `ApplicationAssessment`
   - `AuthorityCheck`
   - `CorrespondenceAssessment`
4. إذا كان application/action/correspondence خارج نطاق P5، أضف العقود والحدود والاختبارات السلبية فقط، ولا تفعّل مسارًا يفتح طبقات لاحقة.
5. أضف invariants/validators لحفظ الهوية والمجال والدليل والرتبة والبقايا والأثر ومنع القفز.
6. لا تستخدم قيمًا مزروعة عند نقص البيانات؛ استخدم `Unknown/Deferred/NotApplicable` وفق نمط المشروع.
7. حافظ على التوافق العكسي للواجهات وJSON، واستخدم versioning أو adapters عند الحاجة.
8. لا تنقل المنطق الصرفي إلى HR2S ولا تسمح له بإصدار `Licensed`.
9. لا تنشئ P13 أو سجلًا من 11 مرحلة باسم SLGE.

## المرحلة C — الاختبارات الإلزامية
- اختبار عدم وجود أي shim أو monkey patch لـ`StrEnum`.
- اختبار أن test harness مطابق للbaseline وغير مستخدم لحقن التوافق.
- اختبار عدم وجود تغييرات في vendor مرتبطة بهذه المهمة.
- اختبار runtime proof وعدم الاعتماد على اسم venv.
- اختبار أن Step 6 لا يغلق دون Python 3.11 الأصلي ونجاح مجموعته المستهدفة.
- حفظ `ClaimProvenance` وسلسلة التحويل.
- اكتمال `ConceptContract` وإظهار البقايا عند النقص.
- منع انتقال `IfadahCandidate` إلى final meaning/action.
- بقاء P12 terminal `IfadahCandidate`.
- حفظ قانون الرتبة وعدم رفعها بتكرار الدليل نفسه.
- active blocker يمنع `Licensed`.
- missing required evidence ينتج `Deferred` لا `Batil`.
- الفصل بين intrinsic verdict وoperational status في البيانات والserialization.
- انتشار residuals وعدم إسقاطها.
- اكتمال `TransitionTrace`.
- منع العبور بين المجالات بلا `DomainBridge`.
- `RepairDirective` يرجع إلى مالك سبب الفشل.
- HR2S output مرشح/دليل فقط.
- ملكية Hokom للجذر والوزن والمصدر والمشتقات.
- التوافق العكسي وعدم تراجع اختبارات P4/P5.
- أضف property/invariant tests حيث يناسب.

## بوابة القبول
لا تعتبر المهمة مكتملة إذا:
- بقي ملف محظور موجودًا ولو كان يرفع `ImportError`.
- بقي تعديل في vendor أو test harness لتسهيل الاستيراد أو النجاح.
- كانت البيئة المسماة 3.11 تعمل على إصدار آخر.
- أعلن Step 6 أو التعديل `CLOSED` دون تشغيل مثبت.
- فشل baseline بلا تبرير، أو حُذف اختبار بلا سبب.
- نشأ نوع أو سجل أو مسار مكرر.
- فُتح P6–P12 أو P13.
- اختلطت الرتبة بالحالة، أو اختفت البقايا، أو تغيرت ملكية الصرف.

## ضوابط Git والتغييرات المحظورة
- لا تنشئ commit أو tag أو release أو PR ولا تدمج إلى main إلا إذا كانت تعليمات المستخدم الحالية تأمر بذلك صراحة.
- لا تستخدم `git clean -fdx` أو أي تنظيف شامل قد يحذف عملًا غير متعلق.
- لا تستخدم stash أو reset شامل لإخفاء تغييرات سابقة.
- احذف فقط الآثار المحظورة التي ثبت أنها منشأة للحادثة، واستعد الملفات المتتبعة من أصلها المحدد.
- اترك التغييرات قابلة للمراجعة وقدم diff واضحًا.
